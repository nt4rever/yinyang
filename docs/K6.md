# k6 load testing

Scripts in `k6/` exercise the YinYang API and web routes under load. They log in once per test run, then each virtual user (VU) repeatedly hits health, home, and profile endpoints.

## Prerequisites

1. **Application running** — start the stack and seed the test user:

   ```bash
   make up
   make command:laravel command="php artisan migrate --seed"
   ```

2. **Disable rate limiting** — comment out the limits below so k6 traffic is not throttled. Restore them after testing.

   `bootstrap/app.php` — global API throttle:

   ```php
   // $middleware->throttleApi('api', true);
   ```

   `app/Providers/AppServiceProvider.php` — `api` rate limiter:

   ```php
   // RateLimiter::for('api', function (Request $request) {
   //     return Limit::perMinute(120)->by($request->user()?->id ?: $request->ip());
   // });
   ```

   `routes/api/v1.php` — login route throttle (`10` requests/minute). Comment out the middleware wrapper:

   ```php
   // Route::middleware('throttle:10,1')->group(function () {
       Route::post('login', [AuthController::class, 'login']);
   // });
   ```

   If config or routes are cached, clear them after editing:

   ```bash
   make command:laravel command="php artisan optimize:clear"
   ```

3. **k6 installed** — pick one option:

   **macOS (Homebrew)**

   ```bash
   brew install k6
   ```

   **Debian / Ubuntu / WSL**

   ```bash
   sudo gpg -k
   sudo gpg --no-default-keyring --keyring /usr/share/keyrings/k6-archive-keyring.gpg \
     --keyserver hkp://keyserver.ubuntu.com:80 \
     --recv-keys C5AD17C747E3415A3642D57D77C6C491D6AC1D69
   echo "deb [signed-by=/usr/share/keyrings/k6-archive-keyring.gpg] https://dl.k6.io/deb stable main" \
     | sudo tee /etc/apt/sources.list.d/k6.list
   sudo apt-get update
   sudo apt-get install k6
   ```

   **Docker** (no local install)

   ```bash
   docker run --rm -i -v "$(pwd)/k6:/k6" -w /k6 grafana/k6 run smoke.js
   ```

   When using Docker on Linux, add `--network host` if `localhost:8000` is not reachable from the container.

4. **Test credentials** — defaults match `AdministratorSeeder`:

   | Variable      | Default              |
   |---------------|----------------------|
   | `BASE_URL`    | `http://localhost:8000` |
   | `K6_EMAIL`    | `test@yinyang.io`    |
   | `K6_PASSWORD` | `password`           |

## Scripts

| Script       | Purpose | Default profile |
|--------------|---------|-----------------|
| `smoke.js`   | Quick sanity check after deploy or config change | 1 VU for 45s |
| `load.js`    | Sustained traffic at a moderate level | Ramp to 10 VUs, hold 5m, ramp down |
| `stress.js`  | Find breaking point under rising load | Ramp to 50 VUs over ~11m |

All scripts share `common.js`, which:

1. `POST /api/v1/login` — obtain a bearer token
2. `GET /health` — Laravel health check
3. `GET /` — home page
4. `GET /api/v1/profile` — authenticated profile

## Running tests

From the project root:

```bash
# Smoke — run this first
k6 run k6/smoke.js

# Load
k6 run k6/load.js

# Stress
k6 run k6/stress.js
```

### Environment overrides

```bash
BASE_URL=http://localhost:8000 \
K6_EMAIL=test@yinyang.io \
K6_PASSWORD=password \
k6 run k6/smoke.js
```

**Load test tuning**

| Variable            | Default | Description              |
|---------------------|---------|--------------------------|
| `K6_LOAD_VUS`       | `10`    | Peak virtual users       |
| `K6_LOAD_RAMP_UP`   | `1m`    | Ramp-up duration         |
| `K6_LOAD_HOLD`      | `5m`    | Steady-state duration    |
| `K6_LOAD_RAMP_DOWN` | `30s`   | Ramp-down duration       |
| `K6_PAUSE_SECONDS`  | `0.5`   | Sleep between iterations |

```bash
K6_LOAD_VUS=20 K6_LOAD_HOLD=10m k6 run k6/load.js
```

**Stress test tuning**

| Variable              | Default | Description        |
|-----------------------|---------|--------------------|
| `K6_STRESS_MAX_VUS`   | `50`    | Peak virtual users |
| `K6_PAUSE_SECONDS`    | `0.3`   | Sleep between iterations |

```bash
K6_STRESS_MAX_VUS=100 k6 run k6/stress.js
```

### Docker examples

```bash
docker run --rm -i \
  -v "$(pwd)/k6:/k6" -w /k6 \
  --network host \
  -e BASE_URL=http://localhost:8000 \
  grafana/k6 run load.js
```

## Thresholds

Each script defines pass/fail thresholds. k6 exits with code `0` when all thresholds pass, non-zero otherwise.

| Script  | `http_req_failed` | `checks`   | `http_req_duration` |
|---------|-------------------|------------|---------------------|
| smoke   | `< 1%`            | `> 99%`    | —                   |
| load    | `< 5%`            | `> 95%`    | p95 `< 800ms`       |
| stress  | `< 10%`           | `> 90%`    | p95 `< 2000ms`      |

## Troubleshooting

- **429 Too Many Requests** — rate limiting is still enabled; follow step 2 in Prerequisites and run `php artisan optimize:clear`.
- **Login fails (non-200)** — confirm the app is up (`curl http://localhost:8000/health`) and the database is seeded.
- **Connection refused** — run `make ps` and ensure the `laravel` service is healthy on port `8000`.
- **High failure rate under load** — check `storage/logs/laravel.log`, Horizon, and Octane worker limits; reduce `K6_LOAD_VUS` or increase `K6_PAUSE_SECONDS`.
- **Docker k6 cannot reach app** — use `--network host` on Linux, or set `BASE_URL` to the host gateway (e.g. `http://host.docker.internal:8000` on Docker Desktop).
